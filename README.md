# SNS投稿の地理・時系列可視化デモ

## 公開アプリ

https://sns-visualization.vercel.app/

## ソースコード

https://github.com/m02311092ys8-bit/sns-visualization

卒業研究「SNSにおける情報の広がりと感情の可視化」の一環として制作したWebアプリです。
東日本大震災時の位置情報付き投稿アーカイブを使い、地図と時間操作を組み合わせた表示を試作しました。
個々の実際の投稿時刻が含まれていないため、再生には人工時刻を使用しています。
このREADMEは震災デモ版の説明です。公開URLの内容は、更新ファイルをGitHubへ反映してVercelのデプロイが完了すると切り替わります。

## 制作の背景と目的

SNSでは、災害、流行、バズ、炎上などに関連する情報が短期間で大量に投稿されます。
文章を順番に追うだけでは、投稿の全体像や地域ごとの偏りを把握しにくいと考えました。
そこで、情報の広がりや感情の変化に関心がある人が、地図と時間を操作しながら投稿を確認できる仕組みを目指しました。
卒業研究では、将来的に拡散の特徴と感情の変化を分析し、炎上の兆候の把握や予測につなげることを目標としています。
今回の作品は、その基盤となる可視化と操作の試作です。

## 実装した機能

- Mapbox GL JSによる地図表示とズーム・移動
- 全5,765件の投稿位置の表示
- 人工時刻を使った24時間の再生・停止
- 時間スライダー、再生速度変更、先頭へのリセット
- 表示時刻までの投稿を残す累積表示と件数表示
- 点のクリックによる投稿本文・人工時刻の表示
- データ取得や地図読み込みに失敗した際のメッセージ表示

スライダーを右端へ動かすと全5,765件を表示します。時刻を戻すと、その時点までの投稿だけを表示します。
件数は地図の表示範囲に関係なく、データ全体で集計します。

## 工夫と改善の過程

### 投稿を消さず、積み重なりを確認できる表示

当初は直近30分間の投稿だけを表示していましたが、時間が進むと点が消え、投稿の積み重なりを確認しにくいと感じました。
そのため、表示時刻を迎えた投稿を残す累積表示に変更しました。
拡大して個別の本文を見る操作と、引いて全体の分布を見る操作を組み合わせています。

### データの制約を画面に示す

国内災害のデータを調べる中で、投稿IDのみの配布、配布終了、時刻の欠落などの制約がありました。
そこで、時刻が欠けているデータを実測値として扱わず、固定した乱数による人工時刻を付け、再生機能のデモに使用しました。
人工時刻であることは、画面上部・ポップアップ・説明文に明記しています。

### 必要性と費用を考えた背景地図の選択

航空写真の表示も試しましたが、利用中のMapboxアカウントでは画像取得が制限されました。
投稿の位置と累積変化を確認する目的を優先し、通常の地図を使用する構成にしました。

## データについて

出典：渡邉英徳研究室「東日本大震災ツイートマッピング」

- https://tweet.mapping.jp/
- https://github.com/wtnv-lab/tweetMapping
- 使用ファイル：developブランチのdata/czml/tweets.jsonと同じ内容の5,765件
- 出典が説明する収録期間：2011年3月11日14:46から24時間以内
- 元の投稿本文・座標・件数は変更していません。
- 配布ファイルには個々の実際の投稿時刻は含まれていません。

加工後ファイル：web/public/data/tweets_simulated_24h.json

追加項目：

| 項目 | 意味 |
| --- | --- |
| simulated_at | JSTで表した人工時刻 |
| simulated_elapsed_seconds | デモ開始からの経過秒（0〜86,399） |
| time_is_simulated | 人工時刻であることを示すtrue |

Pythonのrandom.Random(20110311)を使い、元データの並び順で1件ずつrandrange(86400)を実行しました。
デモの開始時刻は2011-03-11T14:46:00+09:00です。

### このデモで分からないこと

- 実際の投稿順序、投稿数の時間変化、拡散速度
- 誰から誰へ情報が伝わったか
- 地域の被害の大きさや、SNS利用者全体の傾向
- 炎上の発生やその予測

人工時刻の累積表示は、実際の震災時の情報伝播を再現するものではありません。
背景は現在配信されている地図であり、震災当時の地理状況を示すものでもありません。

## 使用技術と制作範囲

- JavaScript / HTML / CSS：画面と時間操作
- Mapbox GL JS：地図と投稿位置の描画
- Vite：開発サーバーと公開用ビルド
- Python：データ確認・形式変換・人工時刻の付与
- GitHub / Vercel：ソース管理と公開

既存の投稿アーカイブと地図ライブラリを利用しています。元のツイートを収集した作品ではありません。
生成AIの支援を受けてコード案の作成・修正を進め、要件の検討、データの選択、表示方法の見直しと動作確認に取り組みました。
制作での役割と使用ツールは、提出時にも実際の作業範囲に合わせて説明します。

## ローカル起動

Node.jsとnpmを用意し、webフォルダで実行します。

```powershell
npm.cmd ci
```

web/.env.localに自分のMapbox公開トークンを設定します。

```text
VITE_MAPBOX_ACCESS_TOKEN=自分のpk.から始まる公開トークン
```

```powershell
npm.cmd run dev
```

表示されたLocalのURLをブラウザで開いてください。開発サーバーはCtrl+Cで停止するまで動き続けます。

## ビルドと確認

```powershell
npm.cmd run build
npm.cmd run preview
```

確認する操作：地図の読み込み、累積件数、スライダー、再生・停止、速度変更、リセット、本文表示。
PCに加え、ログアウトしたブラウザやスマートフォンから公開URLを確認します。
